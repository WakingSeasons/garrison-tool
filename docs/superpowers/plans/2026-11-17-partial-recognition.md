# Partial Recognition Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, task by task.

**Goal:** 支持暂停截图、手动补全与按已识别字段分别套用。

**Architecture:** capture/model.mjs负责合并、字段冲突和完整度说明；workspace.js负责套用计划、验证及持久化。新增capture/editor.mjs管理折叠表单；现有干员和敌方页面呈现待核对状态。

**Tech Stack:** 原有静态HTML/CSS/JavaScript，Node内置测试，现有Playwright检查环境。

**Spec:** docs/partial-recognition.md（用户已批准的规则）。

## Global Constraints

- 主按钮「套用已识别内容」，补全入口默认折叠。
- 未识别不等于未BAN，冲突项目不静默选择；模式未知不假定三类。
- 保留阵容、两侧筛选、标记及旧存档兼容；日期2026-11-17。

## Review Focus

- 模式／难度缺失时，26个盟约及已知敌方字段仍可使用。
- 部分BAN保留旧值但明确标记未知，不误隐藏干员。
- Boss与类别独立更新，沿用旧值时标记并可刷新恢复。
- 两图冲突只隔离对应字段，手动选择后解除。
- 无有效字段、非法字段、空类别和多于模式数量的类别不伪造有效结果。

- [ ] 4. 更新v1.1.0介绍及记录，检查差异、发布并核对线上。

## Rulings / Results

- 暂停图的独立模式不应反过来决定识别时的核心盟约排布；模式补选仅用于结果核对。
- 手动BAN操作视为明确确认：解除该盟约的待核对状态；清空BAN视为确认全部可用。
- 审查后补充：模式／难度也可单独保存；旧元数据沿用时明确标记，旧模式不用于推断新截图的特训数量。类别组冲突须显式点击确认，不因修改一个勾选自动解除。
- 2026-11-18：10项模型测试、52项基础回归、真实暂停流程、显式冲突确认与三张原有示例通过；发布日期按完成日期记为11月18日。
